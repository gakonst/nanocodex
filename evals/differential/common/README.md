# Differential runner contract

Python 3.10+, stdlib only. `run.py --cases cases.json --config config.json --out NEW_DIR --repeats 3 --mock` validates plumbing without a model. Native runs require `--allow-native`; **temporary directories are fresh state, not security isolation**. Use a disposable host/VM for consequential runs. Never run adversarial tasks on a personal machine. Fresh workspace, HOME, CODEX_HOME and process per trial; environment allowlist; no inherited project settings/memory. A supplied `--auth-file` is privately copied with mode 0600 into ephemeral CODEX_HOME, following the existing stock fork benchmark. Never commit credentials or traces from private tasks. Endpoint/auth files and arbitrary environment overrides are not copied.

Cases: JSON array of `{case_id,prompt,tags,hard_reason,files:{relative_path:text},checks:[...],split:"train"|"test"}`. Checks: `file_equals` (exact bytes decoded as UTF-8), `file_absent`, `json_equals`, `answer_contains`, `answer_equals`. Graders run twice on the same output; the raw two verdict arrays are retained. All scored criteria must be stated in prompt/instructions. Mock mode materializes the oracle solely for plumbing; never count it as capability evidence.

Configurations: array of `{agent,model,effort}`. Built-ins: `stock_codex` and `nanocodex` (GPT harness). Custom configurations add `argv`, a list with `{workspace}`, `{model}`, `{effort}`, `{prompt}` replacements; no shell interpolation. Without a prompt argument, prompt is supplied on stdin. Custom adapter should emit JSON `{answer,completed,tokens,cost,error}`. Never put credentials in argv/config. Native stock and Nanocodex JSONL are decoded separately; unknown/truncated streams fail closed. Timeouts kill the process group. Nonzero exits and missing completion score zero and remain separately flagged (not silently dropped). Unknown tokens/cost are null, not zero. Stock pricing is deliberately not invented. Model/effort are explicitly passed; a request flag is not proof of provider-effective effort. Inspect captured run/API events before trusting calibration.

Output schema includes required `case_id,agent,model,effort,repeat,score,grader_verdicts,tokens,latency_ms,cost,error,transcript_path` plus split and mock flags. Each trial has one JSONL row and full stdout/stderr transcript. Configurations alternate order per case/repeat; case order is seeded and shuffled. `index.html` is static, escaped, loads nothing remotely, and links to traces. `summary.json` has case-cluster bootstrap CIs (repeats averaged within case), paired deltas, within-noise flags, errors, all-fail cases and saturation warnings. Small-N CIs and synthetic cases are not release-quality evidence.

`hillclimb.py` accepts one baseline and candidate configuration/results pair. Change exactly one model or effort coordinate per round; it never reads failure transcripts or edits prompts. It writes the candidate as kept configuration only if BOTH train and held-out test improve with positive lower CI bounds, at least five cases per split, exact pairing, deterministic grades and no plumbing/mock errors. Otherwise it writes baseline (revert). The artifacts are immutable; existing output paths are refused. Evaluate the output configuration in the next round. This intentionally narrow controller cannot verify semantic 'one change' in arbitrary code/prompt patches, so those are not accepted. Keep test cases on the evaluator side, not the hillclimber's/model's workspace; repeated test reuse can still overfit, so freeze an additional final holdout for release decisions.

`export_nanoeval.py --cases PATH --out NEW_DIR` exports filesystem cases to canonical nanoeval/Harbor task directories. Run with the existing nanoeval CLI: `nanoeval run --task NEW_DIR/CASE --thinking high --vm`. It reuses the same grader and provides task.toml, instruction.md, fixture Dockerfile and tests/test.sh with reward.txt. VM task support is the preferred isolation path for Nanocodex-only validation, not a claim of matched stock-vs-Nanocodex VM execution. Local exporter tests do not establish a working VM. The lightweight paired CLI orchestrator remains separate because nanoeval's current SDK is deliberately Nanocodex-specific.
