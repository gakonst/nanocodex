# Unreal duplicate-output provider acceptance canary (manual, gated)

This is **not** an automatic test or a public endpoint. Run only with an explicitly approved disposable/local subscription test identity and a trusted **host-managed** provider transport binding. Do not read, export, paste, or log any auth file, bearer token, cookie, refresh token, or connection URL. Never deploy the probe to production or point a generic proxy at an operator-provided endpoint. This repository contains no adapter with credential access; the operator's existing managed transport must inject authentication internally, route only to the pinned OpenAI API Responses HTTP origin and ChatGPT subscription Responses HTTP/WS origins, and tag `provenance: 'provider'` only after actual upstream response receipt. No fixture or mock establishes provider acceptance.

Run `node --test scripts/provider-canary/unreal-duplicate-outputs.test.mjs` for structural tests. For live execution, provide a locally trusted adapter module, set `NANOCODEX_UNREAL_CANARY_APPROVED=1`, then run `node scripts/provider-canary/unreal-duplicate-outputs.mjs --live /path/to/trusted-host-adapter.mjs`. The adapter exports `{ liveProvider: true, async create({transport, request}) {...} }`. `provider` is exactly `openai_api` or `chatgpt_subscription`; `transport` is `http` for the API-key path and `http` or `websocket` for subscription. Route through the existing host-managed provider bindings to `https://api.openai.com/v1/responses` (API), `https://chatgpt.com/backend-api/codex/responses` and `wss://chatgpt.com/backend-api/codex/responses` (subscription); never ask this script for credentials. The adapter returns `{ provenance:'provider', provider, transport, httpStatus, terminalEvent, response }` for HTTP and `{ provenance:'provider', provider, transport:'websocket', upgradeStatus:101, terminalEvent, response }` for WS, where `terminalEvent` is the actual SSE/WS event (`response.completed`, `response.failed`, `response.incomplete`, or `error`) and `response` is the parsed upstream Responses object. Do not translate the WS upgrade into HTTP 200 or fabricate a terminal event. Use `responses_websockets=2026-02-06` for WS, bound timeouts, no redirects, no retries, and a fresh session per transport. Preserve the raw provider response status; do not relabel locally rejected requests as accepted.

The probe mirrors the app's streaming Responses Lite wire (`stream:true`, `tool_choice:'auto'`, developer `additional_tools` prefix, and WS `type:'response.create'`); a local fixture verifies shape, not upstream acceptance. For each of three paths (API HTTP, subscription HTTP, subscription WS) the script makes at most two requests: first force one harmless provider-issued `canary_noop` call, then replay its exact `call_id` with an ordered running and terminal `function_call_output` pair. Both outputs omit `status`; the first text matches the Unreal runtime. The second request's full input contains the user message, provider function call, and exactly those two outputs. A completed upstream continuation is transport-level acceptance only; it does **not** establish the model reasoned about the terminal result, correct durable replay, or safe side-effect handling. Record date, route, provider request IDs/status and sanitized rejection category in a private test report; independently verify transport telemetry to rule out synthetic intermediaries. If either path rejects, retain that result rather than working around it with a different wire shape. Do not run under the production agent identity unless explicitly approved.
