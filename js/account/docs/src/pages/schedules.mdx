# Scheduled prompts

Schedules run recurring prompts on managed agents, even after you close the app.
Open a managed conversation and select **Schedules**. Use **Show schedules from
all my agents** to find jobs created in other conversations. Each job offers
**Edit**, **Pause** or **Resume**, and **Cancel schedule**. New schedules belong to
the conversation you opened. The ephemeral homepage chat does not own schedules.

Canceling a schedule deletes its recurring instruction. Pausing keeps it for
resumption. Both prevent future occurrences; neither stops a turn already
accepted or a fresh session already claimed for delivery. Use **Open run** to
inspect that conversation and stop its active turn separately if needed.

## Manage schedules in a conversation

Ask your managed agent to find or change a schedule. The account-authorized tools
are `list_crons`, `update_cron`, and `delete_cron`:

```js
const schedules = await tools.list_crons({});
// Select the intended row from schedules.data, keeping its agent_id and id.
await tools.update_cron({ agent_id: ownerAgentId, id: scheduleId, cron: "30 8 * * MON-FRI" });
await tools.update_cron({ agent_id: ownerAgentId, id: scheduleId, enabled: false });
await tools.delete_cron({ agent_id: ownerAgentId, id: scheduleId });
```

These are agent Code Mode tools. `list_crons({})` discovers schedules across the
account, including paused schedules; supply `agent_id` to list one agent only.
For updates and deletion, omitting `agent_id` targets the current agent.
`update_cron` requires `id` and at least one changed setting, preserves omitted
settings, and cannot create a missing schedule. Set `enabled: true` to resume.
`delete_cron` cancels the recurring instruction; already accepted occurrences may
still finish. These tools require account authorization and are unavailable to
Connect grants.

## Public HTTP API

Use an account API key as a bearer token. These examples assume `NANOCODEX_ORIGIN`
is your managed service origin, `NANOCODEX_API_KEY` is your account API key, and
`AGENT_ID` identifies the agent that owns the schedule.

| Method | Route | Result |
| --- | --- | --- |
| GET | `/v1/agents/:agent/triggers` | `{ "data": [...] }` |
| GET | `/v1/agents/:agent/triggers/:id` | Schedule, or 404 |
| PUT | `/v1/agents/:agent/triggers/:id` | Create (201) or replace (200) |
| PATCH | `/v1/agents/:agent/triggers/:id` | Update supplied fields (200), or 404 |
| DELETE | `/v1/agents/:agent/triggers/:id` | Idempotent cancellation (204) |

Create a schedule with a stable ID:

```sh
curl --fail-with-body "$NANOCODEX_ORIGIN/v1/agents/$AGENT_ID/triggers/morning-review" \
  -X PUT -H "Authorization: Bearer $NANOCODEX_API_KEY" \
  -H 'Content-Type: application/json' \
  -d '{"cron":"0 9 * * MON-FRI","timezone":"Europe/Athens","input":"Summarize what needs my attention.","enabled":true,"session_mode":"new"}'
```

Edit only the time and prompt, preserving the other saved fields:

```sh
curl --fail-with-body "$NANOCODEX_ORIGIN/v1/agents/$AGENT_ID/triggers/morning-review" \
  -X PATCH -H "Authorization: Bearer $NANOCODEX_API_KEY" \
  -H 'Content-Type: application/json' \
  -d '{"cron":"30 8 * * MON-FRI","input":"Summarize my upcoming meetings."}'
```

Pause with `enabled: false`; use the same request with `true` to resume:

```sh
curl --fail-with-body "$NANOCODEX_ORIGIN/v1/agents/$AGENT_ID/triggers/morning-review" \
  -X PATCH -H "Authorization: Bearer $NANOCODEX_API_KEY" \
  -H 'Content-Type: application/json' -d '{"enabled":false}'
```

Cancel the recurring schedule:

```sh
curl --fail-with-body "$NANOCODEX_ORIGIN/v1/agents/$AGENT_ID/triggers/morning-review" \
  -X DELETE -H "Authorization: Bearer $NANOCODEX_API_KEY"
```

To discover schedules across the account, first `GET /v1/agents`. Its `data` array
contains agent IDs. For each agent whose entry in `summaries` does not explicitly
set `may_have_scheduled_jobs` to `false`, list its triggers. Missing or unknown
presence values must remain candidates for older schedules. A candidate can have
no schedules; the trigger list is authoritative. Trigger IDs are unique within
an agent, so keep both the owner agent ID and trigger ID when updating or deleting.

Read requests need `agents:read`. Mutations need `agents:write`; PUT and PATCH
also need `tools:use`. Connect grants cannot manage schedules. Browser requests
use the signed-in account and retain the normal same-origin mutation checks.

## JavaScript SDK

The `nanocodex/managed` client exposes the same schedule API. In a browser it uses
the signed-in account; on a server, supply your managed origin and account API key:

```js
import { Agent } from "nanocodex/managed";

const agent = Agent.open(agentId, { baseUrl, apiKey });
const schedules = await agent.triggers.list();
const schedule = await agent.triggers.get("morning-review");
await agent.triggers.update("morning-review", { cron: "30 8 * * MON-FRI" });
await agent.triggers.update("morning-review", { enabled: false }); // pause
await agent.triggers.update("morning-review", { enabled: true }); // resume
await agent.triggers.delete("morning-review"); // cancel future occurrences
```

`agent.triggers.update(id, patch)` sends PATCH with a
`Partial<CronTriggerConfig>`, preserving omitted fields. It updates an existing
schedule and returns the saved schedule. Use `agent.triggers.put(id, config)` to
create or replace a complete configuration. Both operations follow the timing
and running-turn semantics below.

## Schedule semantics

The writable fields are `cron`, `input`, `timezone`, `enabled`, and `session_mode`.
PATCH preserves omitted fields. A concurrent edit can return 409; read the
current schedule again before deciding which changes to submit. PUT replaces the configuration: `cron` and `input`
are required, `timezone` defaults to UTC, and `enabled` defaults to true. Omitting
`session_mode` on an existing schedule preserves its mode; new schedules default
to `new`. An identical retry preserves the next occurrence. A changed configuration
starts at the next matching time; resuming does not backfill missed times.

Cron expressions have five fields: minute, hour, day of month, month, weekday.
Use an IANA time zone; local times follow daylight saving transitions. Schedule
IDs use 1–64 letters, digits, underscores, or hyphens. Prompts must contain non-empty text.

With `session_mode: "new"`, each occurrence creates a fresh conversation using
the source agent’s model settings and account permissions. Include all needed
context in the prompt. With `session_mode: "continue"`, each occurrence adds a
turn to the owning conversation and skips that occurrence while it is busy.
Missed occurrences coalesce and are not replayed individually.

`next_run_at` is null while paused. `last_run_at` is a dispatch timestamp, not
proof of completion. Inspect `last_turn_id` in `last_agent_id` to follow the run;
for older schedules without a last agent ID, use the owning agent. Times are Unix
milliseconds. Deleting a schedule preserves conversations already created by it.
