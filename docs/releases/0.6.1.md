# Nanocodex 0.6.1: durable agents, embedded or hosted

Build your own coding agent without rebuilding the agent runtime.

Nanocodex 0.6 brings durable execution, connected accounts, and real execution environments to the same library-first stack. Run agents through the hosted Nanocodex API, or embed the Rust runtime in your own product with your own storage, tools, interface, and infrastructure.

## A hosted API built on durable execution

The hosted API owns long-lived agents: retained conversations, prompt admission, resumable event streams, steering, cancellation, and scheduled prompts. Clients can reconnect to the same agent instead of reconstructing a conversation from their last HTTP response.

- **Connected accounts.** Connect authorizes services such as GitHub, Google, Slack, X, ChatGPT, and custom MCP servers. Connection lifecycle and credential handling live in the service, with scoped grants for consuming applications.
- **Hands.** Attach execution environments to an agent: local machines, SSH hosts, retained VMs, Docker, and cloud sandboxes. Agents can work across multiple environments through named mounts and caller-owned tools.
- **Credential-aware egress.** Brokered outbound requests use authorized connections while provider secrets remain in the credential service.
- **A terminal for hosted agents.** `nanocodex2` signs in, starts or attaches to agents, connects local workspace tools, and supports live steering and queue withdrawal.

Start with the [managed service](https://github.com/gakonst/nanocodex/blob/v0.6.1/js/managed/README.md), [Rust client](https://github.com/gakonst/nanocodex/blob/v0.6.1/crates/nanocodex-managed/README.md), or [nanocodex2](https://github.com/gakonst/nanocodex/blob/v0.6.1/bin/nanocodex/nanocodex2/README.md).

## The library gets the same building blocks

For applications embedding Nanocodex directly, 0.6 is a substantial runtime release independent of the hosted service.

**Durability with your own storage.** `nanocodex-durability` is an optional layer over the agent. Attach memory, SQLite, Postgres, or host-provided storage to retain operation identity, committed model/tool outputs, and recovery state. Recovery uses current execution state and immutable records. Committed outputs replay; unfinished external calls may execute again, so external effects are not exactly-once.

**Reusable subagent orchestration.** `nanocodex-subagents` adds a shared task tree, mailboxes, lifecycle controls, and tools for native and WASM embeddings. It builds on the retained sessions and spawn/fork primitives already available in 0.5. Your application still owns its UI, task-tree persistence, and product policy.

**More control over running agents.** Identified steering can be withdrawn before it reaches a model boundary. Clean children can select model and reasoning overrides. Read-only context access and backend-neutral handles make integration easier without introducing a second agent loop.

**Tools that travel with the application.** Native and embedded hosts share a tool recipe. Code Mode hosts can support resumable cells; reverse attachments let managed agents invoke tools owned by another process. MCP gains coordinated OAuth refresh, per-tool concurrency declarations, and optional paid-call handling.

**Expanded browser and voice integrations.** Browser adds persistent virtual credentials, host passkeys, and frame-aware WebMCP tools. Realtime supports caller-owned media and sideband attachment to existing calls. Voice now has separate protocol, native-client, and C integration layers.

See the [durability guide](https://github.com/gakonst/nanocodex/blob/v0.6.1/crates/nanocodex-durability/README.md) and [subagent example](https://github.com/gakonst/nanocodex/blob/v0.6.1/crates/nanocodex-subagents/README.md).

## Rust upgrade: read this before bumping the version

The [0.5 → 0.6 Rust API migration guide](https://github.com/gakonst/nanocodex/blob/v0.6.1/docs/MIGRATING_0_6.md) includes before/after examples and source references. The main changes are:

- `TurnResult::usage()` and `snapshot()` return `Option`; `session_id()` returns `&str`. Prompt wrappers now convert to `PromptRequest`.
- Default model/reasoning changes from Sol/high to **Astra/low**. Set both explicitly if you want to retain the old selection.
- Snapshot resume retains conversation history but uses the current builder's instructions and tool definitions. Applications requiring an exact policy match should version their own resume envelope.
- Embedded tool APIs move from `hosted` to `embedded`; Code Mode execution and wait return `Result`. Protocol literals gain asynchronous fields.
- Billing-uncertainty metrics and generic MCP resource helpers are removed. Update accounting consumers and prompts that name those helpers.

Rust 1.97 and edition 2024 are unchanged. Durability is available in the default facade features but only becomes active when a store is attached.

## Package status

Browser, egress, VM, and voice leave the experimental package paths. Evals and computer retain the experimental label. The experimental computer client is included in the registry release; browser, egress, and VM remain source packages while pinned dependencies prevent crates.io publication.

The release includes 15 Rust crates, the `nanocodex`, `nanocodex-tools`, and `nanocodex-vite` npm packages, and native `nanocodex`, `nanocodex2`, and computer companion binaries for Apple Silicon macOS and x86-64 glibc Linux.

## CLI installation and voice

0.6.1 also fixes native voice distribution. The macOS and Linux release bundles now include the voice helper, private native libraries, plugins, and license notices. Installation and updates verify the archive and install it alongside the matching CLI. Missing or corrupt cached runtime files are repaired before activation.

An older updater may install the new executable without understanding the voice archive. The new CLI repairs that managed installation automatically on first voice use, fetching the runtime for its exact release and verifying checksums. Bluetooth speaker restarts also refresh the device sample rate after microphone activation. No native SDK or source build is required for release installations.

Rust and JavaScript APIs are unchanged from 0.6.0. Use **0.6.1** for CLI installs; the already-published 0.6.0 registry versions remain available.

## Install

```sh
curl -fsSL https://nanocodex.paradigm.xyz | bash
```

Existing installations can run `nanocodex update`. Binary release assets are covered by `SHA256SUMS`.

```toml
nanocodex = "0.6"
```

```sh
npm install nanocodex@0.6.1
```
