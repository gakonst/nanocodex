# iOS chat interaction audit

This change was driven by automation of the signed-in app on a physical iPhone 17 Pro running iOS 26.6.1. The audit exercised real conversation switching, the history drawer, edge gestures, transcript scrolling, tool expansion, and typing/clearing an unsent draft. No test messages were sent to live conversations. Private screenshots, conversation identifiers, and raw traces are excluded from the repository.

## Device evidence

A 31.461-second Time Profiler capture of the previous Release build sampled 11.809 CPU seconds, of which 11.315 (95.82%) were on the main thread. Inclusive sampled stacks included `InboxModel.focused` (2.407 seconds), `AgentComposerView.body` (1.635 seconds), and roster reconciliation (0.887 seconds, including 0.663 seconds in sorting). These overlapping statistical sample weights are not operation latency or a controlled speedup benchmark. No >250 ms potential-hang records appeared in this capture; this does not establish smooth frame rendering.

Physical-device automation also found duplicate cancellation text and, after an edge-swipe drawer dismissal, an accessibility tree that exposed the entire transcript viewport as the latest-messages button. The visible transcript remained drawn. Button-based drawer opening/closing preserved four measured message anchors with zero point drift in the sampled case.

A later 30-second capture of the updated signed app sampled 7.368 CPU seconds, including 4.417 on the main thread. Focused-card lookup accounted for 0.034 seconds and composer body evaluation for 0.094 seconds of inclusive samples. The interaction mix differed, so these values are diagnostic follow-up evidence, not a matched speedup claim. Notification-summary preparation remained visible (0.362 seconds) and was subsequently moved off-main as well. On the updated physical app, an edge-swipe drawer open/close retained eight common message anchors at zero point drift and kept the transcript accessible.

The SwiftUI trace exporter failed to finalize. Its host-side processing/memory overhead is excluded from app measurements. WebDriverAgent request durations include automation and accessibility overhead and are not treated as UI latency.

## Changes

- Retain queue and focused-card projections across unrelated model changes; cache invalidation uses relevant revisions instead of transcript-array equality on each keystroke.
- Prepare transcript grouping, generated-media parsing, and refresh-time roster sorting away from the main actor. Publish immutable results only after checking their conversation/revision. UI state publication remains on the main actor.
- Reuse the prepared history projector when streaming begins, and expose bounded signposts for transport, decoding, projection, media preparation, and row publication.
- Decode attachment thumbnails according to viewport demand.
- Show attributed computer captures through a conversation-level latest-screen viewer. Filter matching nested/outer Code Mode copies from inline media. Preserve ordinary images and use completion order for overlapping captures. Older history cannot replace the retained latest capture.
- Send during an active turn steers directly, with persisted input, attachments, target and message identity. Only a definitive terminal-target rejection permits a normal follow-up; uncertain delivery is retained rather than automatically resubmitted. Local message positioning remains stable as later output arrives.
- Include agent IDs/roles and bounded prompt excerpts in delegation/message tool summaries. Suppress duplicate cancellation and routine steering-status noise.
- Follow new content while at the bottom, resume continuous following after jumping to the bottom, and preserve semantic reading anchors during sidebar navigation. Keep the latest button outside the scroll view's accessibility node.

Images emitted by arbitrary code without computer-tool attribution remain ordinary image outputs. The screen viewer shows captured snapshots, not an independent live video stream.

## Validation

Core tests cover cache invalidation/work counts, steering persistence, terminal-rejection classification, attachment retention, message ordering, tool summaries and cancellation deduplication. The media package covers output parsing and provenance. `python3 apple/Tests/InboxModelTests/test_screen_projection.py` exercises the actual media projection against synthetic nested/outer results, late attribution, out-of-order capture completion, older paging, eviction, and reset.

UI regressions cover draft edits without transcript regrouping, bottom following, subsequent arrivals after a jump, sidebar button/edge gestures, expanded-tool anchors, cached-tab reading positions, default steering, uncertain receipt restoration, withdrawal, and idle-send cancellation/retry. Physical-device verification remains separate from synthetic UI fixtures; neither constitutes an exhaustive claim that all UI or performance bugs are eliminated.

The default-steering interaction follows [Amp's description](https://ampcode.com/news/steer-dont-queue). Performance work follows Apple's guidance to [measure SwiftUI updates and reduce unnecessary work](https://developer.apple.com/documentation/xcode/understanding-and-improving-swiftui-performance).

## Follow-up: tool arrival motion

Live feedback identified abrupt movement as tools arrived. The follow path explicitly disabled animation, while bottom anchoring also adjusted content-size changes. Following now animates the scroll offset with a short native smooth animation after rendered height changes; top size-change anchoring avoids a competing bottom snap. Projection publication no longer issues a duplicate scroll before layout. Initial positioning, history restoration and Reduce Motion remain immediate. The jump control stays hidden while following, and deferred arrivals catch up after a stationary touch ends. A synthetic sequence of individual tool cards exercises following and jump-control visibility alongside existing streaming, keyboard and reading-anchor regressions.
