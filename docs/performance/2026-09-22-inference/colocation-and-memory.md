# Inference admission and placement

Repeated Markdown startup reads accounted for 190–307ms of warm admission in the measured fixed-Astra cohort. Cache those bounded excerpts per live runtime and authority for 15 minutes, invalidate around explicit writes, and retain the original expiry on hits. Explicit memory tools continue to read current storage. Failed/uncertain writes invalidate; failed bootstrap reads are not cached. Other-session writes and background consolidation may take up to the TTL to appear in startup context. New startup, per-scope bootstrap, append and cache spans expose the remaining cost without logging contents or authority keys.

Placement must follow the original trusted user ingress through nested object creation. A shared public package helper derives first-use hints from platform or retained Session metadata, replaces caller-supplied placement headers on private binding requests, and leaves durable identities unchanged. It covers account/organization initialization, API keys, Sessions, inference Sessions, memory, and credential/connector broker first touches. Scoped environments do not replace retained runtime binding identities or partition discovery caches per request.

Text and voice relays choose separate `text-v1` and `voice-v1` controller identities within region-constrained container applications. Seven subclasses share the same relay implementation/image. Six applications use exclusive supported regions; the OC application includes APAC fallback because OC cannot be exclusive. Each new application has at most 50 instances; the existing legacy application remains available for staged/unknown-region fallback. Containers allocate on use. Voice sideband remains a direct provider call-ID attachment, preserving the upgraded connection.

Cloudflare distinguishes Worker invocation placement, first-use Durable Object placement, and actual container placement. Service bindings normally execute on the same server/thread. Durable Object hints are best effort and do not relocate existing objects. Container constraints bound eligible regions but do not guarantee the controller and container share a colo. Consequently a global Smart Placement toggle or global WNAM pin would not solve this multi-user topology. See [service bindings](https://developers.cloudflare.com/workers/runtime-apis/bindings/service-bindings/), [DO location](https://developers.cloudflare.com/durable-objects/reference/data-location/), [Worker placement](https://developers.cloudflare.com/workers/configuration/placement/), and [container placement](https://developers.cloudflare.com/containers/concepts/placement/).

## Release dependency

The account Worker owns the new relay classes and applications. Deploy those classes/migrations/applications before the egress Worker references them, then deploy the managed caller. This additive staging is required before the usual final account deployment order can resume. Keep credential object keys, encryption associated data and refresh ownership unchanged. First-use hints cannot migrate an existing remote credential broker; its remaining round trip must be reported separately.

## Verification

Focused workerd tests cover original-ingress trust, public spoof rejection, first-touch object identity, fresh authorization, authority-scoped memory TTL and invalidation, cache cancellation/failure, regional text/voice pool selection, credential refresh/account failover, and sideband call-ID/upgrade preservation. Native Node tests cover all regional controller subclasses and constraints. Managed, egress and account typechecks validate cross-package contracts. Browser/native voice simulation exercises negotiation parallelism and cleanup without recording a microphone or creating phone calls.

Production validation must record exact Worker versions, container application constraints, actual instance locations, cold versus warm instances, and foreground correlation IDs. Connection-only voice measurement is distinct from first audible output and voice-delegated text TTFT. Do not infer a physical location from a region hint or add overlapping preconnection/admission intervals.

Production enables the existing voice relay RPC after compatible account classes deploy. SDP and its complete answer travel in one RPC result, avoiding a separate cross-object response-body read. An ambiguous RPC failure is not replayed through HTTP. The private voice sideband entrypoint also reuses the managed ingress ownership check; generic egress still resolves ownership normally.
