# Explicit terminal routing opt-in

`nanocodex2` supports `/autoroute` before the first message, using the same conversation-lifetime guard as `/model`. The slash actions menu and keybindings help list the command. It requires no arguments, never becomes a model prompt, and cannot enqueue a slash command through Enter or Tab. Attached images produce a local usage error while preserving the draft.

The terminal pauses submission until the authenticated opt-in receipt arrives. A command issued during initial connection waits for the new agent ID. The choice is local to that session and never carries into a new thread. The first actual message drives Jev's provider/model/effort selection; subsequent messages retain the pinned route. The model footer shows `Auto · choosing…` until selection, then the actual model, provider and effort (for example `glm-5.3 · Vercel` and `high`). Read-only retained-state refreshes update it during selection and on reconnect, independently of child model events. Late results from a different session or an obsolete opt-in generation cannot overwrite it. Starting a new manual thread resets routed choices to normal defaults instead of leaking GLM or its provider into non-routed admission. Subagents select independently.

The new `POST /v1/agents/{id}/routing` endpoint accepts an empty body or `{}`. Full-account authorization, the deployment routing gate and AI binding are required. Its mutation shares the settings reservation queue; admission rechecks that queue after asynchronous history lookups so a racing first prompt cannot escape the policy. Previously accepted messages, snapshots, imported/retained history and child activity prevent enabling. Existing opt-ins are idempotent. Enabling retires any speculative, unused model runtime and preserves unrelated configuration. Neither the API deployment nor this command enables background probes by default.

Native `nanocodex` still lacks production provider-router composition. It recognizes the command but explicitly reports it unavailable instead of claiming success or dispatching it as a prompt. Earlier native routing checks used an external adapter. Native production routing is not completed by this change.

Validation:

- 549 managed terminal unit tests pass, including autoroute parser/menu/guard/queue and route-display cases; two pre-existing ignored tests remain ignored.
- Three actual `nanocodex2` PTY journeys pass against a controlled HTTP/WebSocket service: enable on a fresh thread and lock after its first prompt, reject attached history, and allow an attached empty thread. The fixture verifies endpoint counts, absence of slash-command prompts, and a real footer transition from startup Astra to a synthetic selected GLM/high Vercel route. It disables unrelated local computer-runtime discovery; an initial run exposed that fixture dependency and is retained in local evidence.
- 29 real workerd coordinator/admission tests pass, including real empty-session creation plus speculative runtime preparation, API authorization, invalid bodies, existing history, settings locking and racing prompt admission.
- Two Rust managed-client HTTP contract tests pass, including actual route projection, pending selection, legacy server defaults and rejection of unknown providers. Two native command tests verify the explicit unsupported message and absence of prompt dispatch.
- Two new real-workerd/Rust-WASM integrations start with an empty non-routed agent, enable through `POST /routing`, then exercise OpenRouter and Vercel Sol/low roots with independently selected Workers AI GLM/high children. Actual tools cover spawn, wait, message/delegation, list, close, child Just Bash reads and structured submission. Two idle shutdown/reconstruction cycles and client reconnects retain parent and child pins without another chooser call. GET state remains the root provider/model after child actions, so the footer cannot adopt a child's route. Model/identity/ancillary responses are synthetic; no provider latency or quality claim follows from these tests.
- Three Rust interruption/recursive-close/continuation tests, eight subagent authorization tests and 82 focused adapter/Rust-WASM tests pass, covering gateway custom tools, cross-provider child routing and checkpoint recovery.
- Managed TypeScript checking passes.

No live provider calls were needed for this UX change. Provider selection/inference coverage remains recorded in the earlier gateway and TTFT reports. This PR has not been deployed.
